# ProtoWatch 产品需求文档

版本：0.3 草案  
更新日期：2026 年 10 月 19 日  
当前阶段：MVP 实现与验证，完整首版需求保留

ProtoWatch 帮助开发和测试人员回答三个问题：当前能观察到哪些 DDS 实体，哪些 Topic 正在传输数据，以及发现和通信异常有哪些可核查的线索。目标是一个可在开发机或测试现场使用的小工具。

已确认面向通用 DDS，重点覆盖 Fast DDS 和 Cyclone DDS；ROS 2 作为尽量兼容的扩展目标，能够复用现有能力时纳入，需要专门适配时暂缓，不阻塞通用 DDS 首版。以下首版范围、平台与性能指标为建议方案，作为后续实现和评审依据；不代表已经实现或完成兼容性验证。

已确认部署要求为 **Linux ARM64、网页观察、单个二进制程序**。先实现范围更小的 MVP0：实时采集、classic PCAP 导入、基础发现、未分片样本原始载荷、统计及 JSON 导出。下文“首版”保留为完整产品目标，不能视为当前 MVP 已支持；逐项实现范围、技术栈和部署方法见[技术方案](TECHNICAL_DESIGN.md)。IDL 解码、分片重组、PCAPNG 和完整证据包不属于当前 MVP0。

## 1 产品目标

用户启动工具后，应能沿着“选择观察来源 → 找到 Topic → 查看发布端和订阅端 → 检查样本 → 导出问题证据”的路径完成一次排查。

| 用户问题 | 工具提供的答案 |
| --- | --- |
| 网络里有什么 | 当前观察范围内的 Participant、Topic、DataWriter、DataReader 清单 |
| 谁在发什么 | Writer 对应的 Topic、类型、网络地址和实际捕获的样本 |
| 谁可能接收 | 已发现的 Reader、相关 QoS 和候选关联，标明关联依据 |
| 数据是什么 | 支持类型的字段树和 JSON；无法解码时显示原始字节及原因 |
| 传输是否活跃 | 观察到的样本频率、载荷速率、最后出现时间和变化趋势 |
| 为什么看不到数据 | 类型缺失、观察范围不足、QoS 差异等线索及对应证据 |

首版成功标准：无需修改被观察应用，用户能够用一份完整的受支持抓包定位 Topic、查看一条已知类型样本，并导出可复查的记录。实时观察使用同一套界面与解释规则。

## 2 目标用户和主要场景

主要用户是 DDS 应用开发者、系统集成人员和测试人员。默认用户了解发布订阅概念，但不需要熟悉 RTPS 报文结构。

1. **接入摸底**：接入一个已有系统，快速了解参与者、Topic、数据类型及发布订阅分布。
2. **数据核对**：找到某个 Topic，检查字段值、样本大小和频率是否符合业务预期。
3. **发现排查**：启动或关闭应用，观察参与者和端点的发现、更新、移除事件。
4. **通信排查**：Topic 已发现但没有样本，检查采集位置、类型状态和端点配置差异。
5. **离线复盘**：导入现场抓包，在不连接原网络的情况下复查实体、样本和事件。

## 3 术语和观察边界

### 3.1 服务发现的含义

本产品首版的“服务发现”指 DDS 实体发现。SPDP 用于参与者发现，SEDP 用于读写端点发现；界面从端点公告汇总 Topic 及类型信息。[Fast DDS SIMPLE Discovery](https://fast-dds.docs.eprosima.com/en/latest/fastdds/discovery/simple.html)

| 术语 | 产品中的含义 |
| --- | --- |
| Domain | DDS 通信域；无法确认编号时归入未知域，并保留推断来源 |
| Participant | DDS 参与者，以 GUID 标识；不直接等同于主机、进程或业务服务 |
| Topic | 具有名称和类型关联的数据主题；同名但类型不同的记录分别展示 |
| Writer / Reader | 发布和订阅数据的端点，以完整 GUID 区分 |
| Sample | Writer 发出的一个数据样本，可能跨多个 RTPS 分片传输 |
| Instance | 带 Key 类型中的一个数据实例，与样本不是同一概念 |
| 观察会话 | 一次实时采集或文件导入，包含来源、时间范围、配置和解析结果 |

通用 DDS 发现信息不自动等价于业务 RPC 服务目录。ROS 2 Service、Action、节点名恢复以及特定厂商 RPC 映射属于后续适配范围，首版不凭 Topic 名称直接认定其业务含义。

### 3.2 两种观察模式

| 对比项 | 被动观察 | 主动观察 |
| --- | --- | --- |
| 工作方式 | 捕获网卡流量或读取 PCAP 文件 | 以 DDS Participant 加入网络，按需创建 Reader |
| 获得的信息 | 观察位置实际可见的发现和数据报文 | 中间件允许发现的实体，以及匹配订阅实际收到的数据 |
| 对 DDS 网络的影响 | 工具不创建 DDS 实体，不发送 DDS 协议消息 | 产生发现、类型查询及可能的可靠性控制流量，也可能使 Writer 开始发送数据 |
| 主要限制 | 不可见的链路、错过的发现和未知类型都会限制结果 | 受 Domain、发现配置、QoS、权限及厂商能力限制 |
| 规划 | 首版默认能力 | 后续按需开启 |

**首版推荐被动观察优先**，贴合“观察原本有哪些数据在传输”的目标。用户希望主动获取某个 Topic 时，后续通过明确的模式切换实现；两种来源的样本和统计必须分开。

### 3.3 必须准确表达的限制

- 同处一个局域网不保证看见其他主机之间的单播流量。完整观察通常需要在通信主机、合适的网络接口或镜像端口采集；混杂模式不能替代交换机镜像。多播是否可见也取决于网络和接口配置。
- 参与者发现与端点发现可以使用不同的传输路径。看到了 SPDP 不意味着已捕获全部 SEDP 或用户数据。[Cyclone DDS 发现过程](https://cyclonedds.io/docs/cyclonedds/latest/about_dds/discovery_participants.html)
- 共享内存和进程内交付不能依靠普通网卡抓包完整观察。本产品据此将相关流量列为首版可见性边界。[Fast DDS 共享内存传输](https://fast-dds.docs.eprosima.com/en/latest/fastdds/transport/shared_memory/shared_memory.html)
- DDS Security 可以保护整个 RTPS 消息、子消息或载荷，因此发现信息也可能不可读。首版只展示可识别的外层信息和受保护状态，不承诺解密。[Fast DDS 加密插件](https://fast-dds.docs.eprosima.com/en/latest/fastdds/security/crypto_plugin/crypto_plugin.html)
- Domain ID 不能一概从 UDP 端口可靠还原。必须区分报文明确提供、用户配置、默认端口规则推测和未知四种来源；推测不能作为确定的跨实体合并依据。
- 抓到数据不代表所有 Reader 收到数据，端点配置看起来兼容也不证明已经匹配。界面采用“候选关系”“观察到定向通信”等表述，不宣称业务消费成功。
- 捕获中断、序列号缺口或长时间未见实体，都不能单独证明网络丢包或进程退出。所有异常结论应附观察区间和证据。

## 4 首版范围

### 4.1 必须交付的能力

| 编号 | 功能 | 首版范围 |
| --- | --- | --- |
| F01 | 观察会话 | 选择单个网卡实时采集，导入 PCAP / PCAPNG，或重新打开本工具证据包；显示来源、时间范围和采集状态 |
| F02 | 实体发现 | 解析可见 SPDP / SEDP，展示 Participant、Topic、Writer、Reader 及变更 |
| F03 | Topic 总览 | 按名称、类型、参与者筛选，显示端点数、最近数据时间、频率及载荷速率 |
| F04 | 样本检查 | 查看样本元信息、原始字节、受支持类型的字段树和 JSON |
| F05 | 类型导入 | 导入本地 IDL，将明确的类型定义绑定到选定 Topic / Writer |
| F06 | 基础诊断 | 显示部分 QoS 不兼容、类型缺失、分片不完整、序列号缺口及采集异常线索 |
| F07 | 事件时间线 | 查看实体首次发现、公告更新、显式移除、观察超时和解析异常 |
| F08 | 保存和导出 | 保存选定的原始捕获，导出实体快照、样本和诊断证据 |

首版协议支持目标：RTPS over UDP / IPv4、SIMPLE Discovery、常见以太网及 Linux cooked capture 封装。支持 RTPS DATA 和 DATA_FRAG 样本恢复，以及诊断所需的 HEARTBEAT、ACKNACK、GAP 等控制信息。未知参数和子消息尽量跳过并保留原始位置，不应导致整个会话失败。

IPv4 分片需先重组再解析 UDP；不完整重组必须标记。IPv6、TCP、自定义传输和未支持的链路封装返回明确的支持状态，不静默展示为空。

### 4.2 后续增强

| 优先级 | 能力 | 进入条件 |
| --- | --- | --- |
| P1 | 主动发现与按 Topic 订阅 | 验证中间件接口、QoS 行为、停止订阅与资源释放 |
| P1 | XTypes 类型自动获取与更广泛解码 | 验证 TypeLookup、类型依赖、XCDR2 及跨厂商差异 |
| P1 | Fast DDS Discovery Server 适配 | 固定版本和角色配置，验证能够获得的实际发现范围 |
| P1 | 图形拓扑、字段曲线、字段值过滤 | 首版实体关系和样本模型稳定 |
| P1 | IPv6、多接口与远程采集 | 验证去重、时钟和来源隔离 |
| P2 | ROS 2 节点图、Service、Action 与业务服务语义适配 | 基础 DDS 观察可直接复用；专用语义仅在后续有明确需求时投入 |
| P2 | 厂商统计扩展与长期趋势 | 明确专用数据来源，区分协议推断与中间件报告 |

自动类型获取依赖远端提供的信息、类型依赖和实现能力，不能仅凭 TypeName 恢复任意类型。[Fast DDS 类型发现与 TypeLookup](https://fast-dds.docs.eprosima.com/en/2.x/fastdds/dynamic_types/discovery.html)

Discovery Server 的可见范围与版本及客户端角色有关。例如 Fast DDS 3.4.2 文档区分 CLIENT 和 SUPER_CLIENT 的发现信息范围，因此适配时必须固定版本验证。[Fast DDS 3.4.2 Discovery Server](https://fast-dds.docs.eprosima.com/en/v3.4.2/fastdds/discovery/discovery_server.html)

### 4.3 首版不包含

业务数据发布、参数修改、样本重新发送到 DDS 网络、全网自动扫描、完整 RPC 链路追踪、任意厂商私有扩展、共享内存探针、加密流量解密、云端账号与集中监控平台。

离线“回看”仅指在本工具中查看已保存数据，不向原 DDS 网络回放。

### 4.4 ROS 2 可选兼容

优先尝试观察使用 Fast DDS 或 Cyclone DDS 的 ROS 2 系统，沿用首版支持的 UDP、发现和序列化范围。ROS 2 也支持非 DDS 中间件，因此不承诺覆盖所有 ROS 2 配置；例如 Zenoh 不属于本工具的 DDS 抓包范围。[ROS 2 中间件说明](https://docs.ros.org/en/ros2_documentation/kilted/Concepts/Intermediate/About-Different-Middleware-Vendors.html)

| 层次 | 兼容策略 |
| --- | --- |
| 基础观察 | 直接复用 Participant、端点、DDS Topic、原始样本和统计功能，不要求工具安装 ROS 2 |
| 名称展示 | 若规则验证通过，可附加 ROS Topic 名称提示，同时保留原始 DDS 名称和推断标记 |
| 消息解码 | 用户提供与实际线格式一致、且在首版支持范围内的 IDL 时尝试解码；不要求首版直接解析 `.msg`、`.srv` 或 `.action` |
| 专用语义 | 节点归属、Service 请求响应配对、Action 状态及完整 ROS graph 暂不作为首版要求 |

ROS 2 的常规 Topic 名称映射包含 `rt` 前缀，例如 `/foo` 对应 `rt/foo`；名称提示必须可关闭，不能仅凭前缀断定流量来自 ROS 2。[ROS 2 Topic 与 Service 名称映射](https://design.ros2.org/articles/topic_and_service_names.html)

兼容验证只增加代表性样例，不单独建设 ROS 2 适配层。若遇到超出首版范围的编码、类型生成规则、发现方式或传输方式，记录具体限制并回退到可用的 DDS 信息；不为满足 ROS 2 场景扩大首版范围或延后交付。

## 5 功能详细要求

### 5.1 观察会话

实时采集选择接口并展示接口地址、权限状态、采集过滤条件和保存策略。Domain 过滤属于解析后的筛选，不能默认等同于一组固定 UDP 端口。首版每次打开一个会话；停止采集后仍可查询已有结果。

导入文件后显示时间范围、封装格式、包数量和解析进度，支持取消。时间线按捕获时间推进，离线状态不能用当前墙钟时间计算。文件结束时标记“观察结束”，不将所有实体判为退出。

会话页持续显示内核报告的捕获丢弃数、解析失败数、重组超时数和内部队列丢弃数；不可获取的计数显示“不可用”，不能当作零。

### 5.2 实体发现与生命周期

Participant 展示 GUID、可得的厂商和协议版本、公告名称、地址、首次和最后观察时间。进程名、主机名等字段只有在有明确来源时展示。公告 Locator 与实际包源地址分列，不能当作同一事实。

Writer / Reader 展示 GUID、所属 Participant、Topic、类型、Partition、可见 QoS 和状态。空 Partition 按对应 DDS 默认语义解释；无法读取时显示未知。History、Resource Limits 等字段可能无法从现有发现报文获知，不填造默认值。

状态区分“已发现”“近期有通信”“观察超时”“显式移除”。观察超时可参考可见租约和最后活动时间，但含义仅是本观察点未继续看到该实体。因父 Participant 超时而标记的端点必须保留这一原因，不能伪造端点移除事件。

中途开始抓包时，允许先创建“Topic 未知”的 Writer 记录；后续捕获到发现信息后关联已有样本。没有历史发现信息时保留未知状态，不自动发送查询。

### 5.3 Topic 与端点关系

Topic 列表默认展示名称、类型、Writer 数、Reader 数、最后样本时间、样本频率、载荷速率和解码状态。端点数量仅统计本会话已观察到的记录，可切换包含历史失活记录。

同一名称下不同类型指纹分别显示；没有类型指纹时保留“仅名称已知”，不能直接认定结构相同。Partition 用于端点筛选和候选匹配分析，不修改 Topic 的名称。

首版通过端点表表达关系，暂不要求复杂拓扑图。关系展示依据及时间，例如“名称一致，已检查的 QoS 未发现冲突”“捕获到定向 DATA”“捕获到 ACKNACK”。多播数据不能据目标 IP 推导具体业务 Reader。

### 5.4 数据样本与解码

每条样本至少展示捕获时间、Writer GUID、序列号、Topic 关联状态、序列化载荷大小和解码状态。来源时间戳存在时单独显示，不能用捕获时间替代；只有成功恢复 Key 时才能按业务实例聚合。

解码状态包括：已解码、缺少类型、不支持编码、载荷不完整、受保护、类型不匹配或解析失败。失败时保留原始字节和错误定位，不展示猜测的业务字段。JSON 展示 64 位整数时使用不会损失精度的表示；NaN、Infinity 和二进制数据采用带类型说明的表示。

首版用户载荷解码范围限定为 **XCDR1 普通 CDR 编码的 final struct**：基本整数、布尔值、浮点数、字符、字符串、枚举、嵌套结构、定长数组和 sequence，支持大小端。IDL 支持 module、typedef 和受支持成员的组合。union、继承、optional、mutable / appendable 编码及 XCDR2 暂不纳入首版结构化解码，仍保留可见原始载荷。

IDL 导入显示解析结果、支持状态和绑定目标；存在同名类型时由用户明确选择。仅使用本地选定文件及显式提供的依赖，不自动从外网获取 include，也不执行 IDL 内附加命令。记录文件摘要及绑定版本，便于导出后复查。没有可校验的远端类型信息时，标记“按用户绑定类型解码，类型一致性未验证”；错误但布局兼容的 IDL 未必能被自动识别。

样本列表支持按 Topic、Writer 和时间筛选，支持暂停自动滚动、查看详情、复制单条 JSON。暂停滚动不停止采集；停止采集是独立操作。数据处置或注销状态单独标记，不伪装成一条普通业务值。

### 5.5 统计口径

| 指标 | 计算口径 | 展示限制 |
| --- | --- | --- |
| 样本频率 | 每秒完整恢复的唯一用户样本数，默认显示最近 5 秒滑动平均 | 按会话内 Writer GUID 与序列号去重；发现样本和不完整分片不计入 |
| 载荷速率 | 完整唯一用户样本序列化载荷字节数除以窗口秒数 | 不包含协议头，不等于链路带宽 |
| 捕获速率 | 捕获接口报告的原始包长度总和除以时间 | 包含重传和控制流量；截断字节数另外显示 |
| 最近活动 | 最近一次可归属到目标实体的报文时间 | Topic 的最后用户样本时间独立展示 |
| 序列号缺口 | 本观察区间内看到的不连续 Writer 序列号范围 | 允许后续乱序或重传补齐，不直接输出网络丢包率 |
| 重复观察 | 同一 Writer 与序列号的重复样本或分片 | 可能来自重传或采集重复，不自动称为协议重传率 |

分片按样本重组后计数；环形缓存淘汰不回退已经完成的统计。内置发现流量和用户数据分别统计。首版不提供未经测量条件保证的端到端延迟、业务投递成功率或全网总吞吐。

### 5.6 基础诊断

每条诊断包含对象、观察时间、事实、判断、证据包引用和建议检查项；自动判断使用“已知冲突”“疑似异常”“信息不足”三类，缺少证据时不显示确定故障。

首版确定性规则包括 Reliability 与 Durability 的已知不兼容组合；Partition 无交集仅在匹配语义完整实现且信息充分时判定。其他 QoS 先并排展示，不承诺覆盖全部匹配规则。QoS 检查应遵循 Writer 提供能力与 Reader 请求能力的方向关系。[Fast DDS 标准 QoS](https://fast-dds.docs.eprosima.com/en/latest/fastdds/dds_layer/core/policy/standardQosPolicies.html)

典型提示：

- “已发现该 Writer，但当前观察区间未捕获用户样本。请检查是否有匹配 Reader、采集位置及共享内存配置。”
- “已捕获样本，缺少可用类型定义。导入匹配的 IDL 后可尝试解码。”
- “发现序列号缺口，尚不能区分发送侧行为、链路丢失或本机捕获丢弃。”
- “Writer 为 Best Effort，Reader 请求 Reliable，存在 Reliability 不兼容。”

### 5.7 保存与导出

默认实时查看只保留有界内存缓存，用户开启录制后才持续写入原始捕获文件。录制必须配置空间上限；达到上限默认停止录制并保留已写入文件，同时提示实时观察仍在继续。

支持导出实体快照 JSON、事件 CSV、样本 JSONL，以及已保存且适用的 PCAP / PCAPNG。导出遵循当前筛选条件，并明确时间区间、是否包含载荷、是否有截断或缺失。不能将缓存淘汰后的数据宣称为完整导出。

证据包包含会话配置、工具版本、类型定义及其绑定信息、选定结果和可用原始捕获。离线查看能够恢复相同的解码条件；文件内部引用不依赖原机器绝对路径。所有文件默认保存在本地，不自动上传。

## 6 界面与操作流程

采用一个 Linux ARM64 程序完成采集和 HTTP 服务，网页资源内嵌，默认仅绑定设备回环地址。浏览器可通过 SSH 转发访问；显式监听局域网地址后可直接访问，无需登录。macOS 可开发网页及验证离线文件，其他系统的实时采集暂不纳入范围。

| 页面区域 | 内容与主要操作 |
| --- | --- |
| 顶部会话栏 | 数据来源、观察时间、采集或离线状态、可见性提示、丢弃计数、开始与停止 |
| 左侧导航 | 总览、Topics、Participants、事件、类型管理 |
| 总览 | 实体数量、活跃 Topic、用户与发现流量趋势、当前诊断 |
| Topic 详情 | 概览、端点、样本、类型和诊断；点击样本打开详情面板 |
| 样本详情 | 元信息、字段树、JSON、原始字节和关联包位置 |
| 事件页 | 时间与对象筛选，点击跳转对应实体或样本 |

核心操作流程：

1. 启动工具，选择网卡或抓包文件，查看输入是否受支持。
2. 开始观察，在总览确认是否捕获到 RTPS 数据、发现信息是否完整。
3. 在 Topics 中找到目标，查看 Writer、Reader、QoS 和当前活动。
4. 选择样本；若类型缺失，导入并绑定 IDL，然后重新解析仍保留的样本。
5. 查看诊断的证据，导出选定时间段用于复查。

空状态必须区分：没有捕获到包、捕获到包但没有识别出 RTPS、仅发现实体尚无用户数据、样本存在但不能解码、当前筛选无结果。每种状态给出对应操作，不能统一显示“无数据”。

## 7 数据与实现约束

实现围绕“采集输入 → 协议解析与重组 → 实体和样本模型 → 查询与展示”组织。实时和离线输入共用解析规则；后续主动观察通过独立适配器进入模型，并保留来源。

每个实体、样本、事件和诊断都必须带会话 ID 及证据引用。最小模型包括 ObservationSession、Participant、Endpoint、TopicView、TypeDefinition、Sample、DiscoveryEvent 和 Diagnostic。类型名称不作为唯一类型身份，端点不以 IP 地址为唯一身份。

解析必须处理长度越界、异常 sequence 长度、超大样本、循环类型依赖、重复分片和重组超时。捕获、重组、解析、存储和页面刷新分别限流；不能为了刷新界面逐条推送所有高频样本。

建议默认限制：每个 Topic 最近 1,000 条样本，全会话样本及重组载荷合计 256 MiB，单条重组样本最大 16 MiB，重组等待 5 秒。达到任一限制就按明确策略淘汰或拒绝，展示具体原因；这些值可调整，需通过性能验证确定发布默认值。

## 8 非功能目标

以下为首版验收目标，不是已测得结果。基准环境暂定 Linux x86_64、4 核 CPU、8 GiB 内存；使用关闭共享内存的受控 UDP 测试场景。

| 项目 | 验收目标 |
| --- | --- |
| 基础负载 | 20 个 Participant、100 个 Topic、合计 1,000 样本每秒、平均载荷 1 KiB，持续 30 分钟 |
| 展示时效 | 已接收且可解析的发现和样本数据，95% 在 1 秒内更新到界面；不包含等待远端公告的时间 |
| 资源有界 | 基础负载下进程总常驻内存目标小于 1 GiB；达到缓存上限后不随观察时长持续增长 |
| 查询体验 | 已载入数据的常规筛选和样本详情操作，95% 在 500 毫秒内完成 |
| 数据准确性 | 受控无丢弃抓包的唯一样本计数和字段值与发送记录一致；出现丢弃时明确展示 |
| 超载行为 | 按策略降级，显示丢弃和截断；允许停止、导出已有结果，不能卡死 |
| 本地运行 | 无云端依赖；权限不足时说明具体接口问题，并可继续导入离线文件 |

实现前还需确定以下事项；在确认前按本文件建议推进技术验证：

- **设备规格**：Linux ARM64 已确认，仍需确定内核版本、CPU、内存及实际采集网卡；既有 x86_64 性能目标不能代替目标设备实测。
- **实际 DDS 配置**：具体版本、发现方式、传输方式、Domain 和安全配置影响可见性与测试矩阵。

## SOME/IP 增量范围（0.2 MVP）

产品增加 SOME/IP 被动观察能力，同一观察会话同时处理 DDS 和 SOME/IP，网页按协议切换。用户可以查看服务实例、方法和事件、Find / Offer / 订阅与应答记录，以及请求 / 响应 / 通知的原始载荷与统计。

支持 TCP 有界流重组、UDP 多消息、SD 端点与 TTL、实例关联、数字 ID 和 JSON 可读名称映射。状态区分公告有效、已停止公告、公告过期、仅观察到数据；不以公告过期断言设备掉线，不以订阅应答断言数据送达。

保持 Linux ARM64 单二进制、网页访问无需令牌的部署方式。SOME/IP 业务字段解码与 TP 重组不纳入本次增量验收。TCP 支持跨包、粘包、乱序和重传去重；页面区分 TCP / UDP，缺失字节不拼接为完整消息，重组超限与残缺会显示提示。完成清单、限制与使用方式见 [SOME/IP 文档](SOMEIP.md)。
